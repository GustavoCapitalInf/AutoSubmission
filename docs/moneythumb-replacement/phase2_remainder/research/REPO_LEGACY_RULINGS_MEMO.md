## 2. Unlimited OCR — what "Unlimited OCR" actually is in this repository

### 2.1 Identity — DOCUMENTED in repo
- **It is not a SaaS vendor. It is an open-weights vision-language OCR model: `baidu/Unlimited-OCR` on Hugging Face**, loaded with `trust_remote_code` (`local_ocr_server.py:1-18,54-71`; `ocr/config.py:143` default `OCR_MODEL="baidu/Unlimited-OCR"`; `README.md:1-4`).
- Served two ways, both speaking the OpenAI Chat Completions dialect (`GET /v1/models`, `POST /v1/chat/completions`):
  1. **Local ($0 vendor):** `local_ocr_server.py` — a Flask shim on the operator's own AMD RX 7800 XT (ROCm, gfx1101) via transformers + `model.infer(...)` (`local_ocr_server.py:17-18,45-71,107-129`; `requirements-local.txt:1-19` pins `torch==2.9.1+rocm6.3`, `transformers==4.57.1`); `serve_local.sh`. Bound to `0.0.0.0:8000` (`local_ocr_server.py:259`) — note: the server itself binds all interfaces; the client-side policy classifies `localhost` as loopback.
  2. **Remote PAID (RunPod, opt-in escape hatch):** vLLM with the dedicated image `vllm/vllm-openai:unlimited-ocr`, start command `baidu/Unlimited-OCR --trust-remote-code --logits_processors vllm.model_executor.models.unlimited_ocr:NGramPerReqLogitsProcessor --no-enable-prefix-caching --mm-processor-cache-gb 0`; endpoint `https://<pod-id>-8000.proxy.runpod.net/v1`, key `sk-<pod-id>`; ≥8 GB VRAM BF16, RTX 3090 confirmed (`docs/runpod-setup.md:8-23`; `README.md:94-135`; `run.ps1:1-12,24-28`). OQ6 keeps it documented as a labeled escape hatch, never automatic.
- **Architecture family (STRONGLY INFERRED, not stated in repo):** the model's `infer(tokenizer, prompt, image_file, output_path, base_size=1024, image_size=640, crop_mode=True, ...)` signature, its remote `deepencoder.py` module (`requirements-local.txt:15`), the `<|det|>label [x0,y0,x1,y1]<|/det|>` grounding tags and the per-request n-gram logits processor are the DeepSeek-OCR API/architecture surface. The repo never says "DeepSeek"; treat the family identification as inference to be verified by the external research agent.
- History: adopted 2026-07-23 (`0ad20e6 feat: migrate from Nanonets to baidu/Unlimited-OCR`) replacing a Nanonets-OCR2 client (`7a7e57f`, 2026-07-22) that "produced pure repeating-token garbage" (`docs/runpod-setup.md:147-155`). The local ROCm shim and the RunPod doc landed the same day (`56d28b3`, `91cb767`). It was the repository's original front door before the deterministic shift (`README.md:1`, audit `#30`).

### 2.2 Request / response contract — DOCUMENTED
- **Input:** one page image per request (PNG data URI), text block `<image>Free OCR.` BEFORE the image block; `temperature=0.0`; `max_tokens=4096` on the client (`ocr/ocr_client.py:10-11,599-644`); `extra_body={"skip_special_tokens": False, "vllm_xargs": {"ngram_size": 35, "window_size": 128}}` — required or the model returns `""` (`docs/runpod-setup.md:106-130`). Whole-document (multi-page) requests are mentioned as possible with `window_size=1024` but never used (`README.md:43-44`). Pages are rasterised at 300 dpi with a 250-dpi fallback re-OCR when the orphan-amount-table mis-segmentation signature fires (`ocr/pipeline.py:22-25,180-184`; `ocr/ocr_client.py:200-212`).
- **Output:** raw markdown-ish text with HTML `<table><tr><td>` for tables, prefixed by region tags `<|det|>label [x0,y0,x1,y1]<|/det|>` with **0–1000 per-axis normalised coordinates** and labels such as text/table/title/footer/image/figure/logo/signature (`ocr/ocr_client.py:12-17,329-333,344-374`; `docs/runpod-setup.md:134-135`). **So it does return geometry — but REGION/LINE-level, not word-level**, and the tags are orphaned/unclosed at times (`:14-15`). No confidence of any kind is emitted (audit §2.7). Refusal prose can appear inline on graphics (QR codes) (`docs/runpod-setup.md:137-145`). Repetition degeneration is real (the reason `collapse_repeated_amounts` existed). Header/value fusion in tables is real (`split_fused_header_row`).
- **Truncation:** `finish_reason=length` / `max_tokens` and structural open-tag tails are assessed flag-only by `ocr/truncation.py` (`:47-77` signals; the local shim never reports `usage`, `ocr/ocr_client.py:581-583`). Client ceiling 4,096 tokens vs 32,768 on the local shim (`RISK_REGISTER.md` R-11).
- **Postprocess:** all nine cleanup functions quarantined; raw completion goes to the validator (`ocr/ocr_client.py:599-621`).
- **TD page-1 recovery:** five `(dpi, mask_qr)` render variants, declared intake furniture (`ocr/ocr_client.py:245-263,434-...`).

### 2.3 Cost / latency / privacy — DOCUMENTED vs UNKNOWN
- Latency: **~23 s/page** serial on the local path (`PARITY_MATRIX.md` rows 2 and 20; `PRODUCTION_GAPS.md` G7). No per-page latency on RunPod recorded. `OCR_MAX_WORKERS` defaults to 1 because a 24 GB card thrashes KV cache (`ocr/config.py:152-158`).
- Cost: `baidu/Unlimited-OCR` is in `FREE_MODELS` for the LOCAL server by Ocean's W3-5 ruling (`telemetry/prices.py:29-38`); RunPod bills per GPU-hour, **no rate recorded anywhere** (`docs/runpod-setup.md:157-162`). A remote read is evidenced in telemetry by `endpoint_class=remote`, `remote_opt_in=true` (`README.md:16-18`).
- Privacy / data handling: the local path keeps pixels on the operator's machine; page PNGs are written to a temp dir and deleted per request (`local_ocr_server.py:97-104,128-129`). The RunPod path sends page pixels to a third-party GPU host over HTTPS with a guessable key (`RISK_REGISTER.md` R-24); no retention statement exists for RunPod. `embed_image_regions` (pixels into the analysis text) is unwired (F-2 closed).
- **UNKNOWN (not determinable from the repo):** the model's current HF revision/license, whether newer revisions emit word boxes or scores, the exact model size, throughput on an RTX 5090 or 3090, whether the RunPod image still exists, and whether the AMD box is still available. Phase 2.1's Vast worker is Paddle-only; nothing about Unlimited was deployed there.

## 3. Tesseract

- Implementation: `ocr/local_tesseract.py:12-44` — `rasterize_pdf(dpi=200)`, `tesseract <png> <out> --psm 6`, plain `.txt` per page, per-page `except: ""`, 200-character document floor, model token `local-tesseract-ocr`. **No boxes, no confidence, no TSV/hOCR.** Gated `allow_local_ocr` (webapp + discovery `--scanned`).
- Word boxes are technically reachable (`tesseract ... tsv` / `image_to_data`) and were named a future option: `DESIGN_GEOMETRY_INTEGRATION.md:254-269` (with the coordinate-contract hazard that Phase 2.1's `PageFrame` now solves), `PHASE2-1-PADDLE.md:428` (excluded, "documented as a future option"), `BATCH9_TRANSITION.md:361` ("Tesseract word boxes" listed under Phase 2.2 prerequisites).
- Measured quality on the corpus: 179 reads → **36 validated / 15 withheld / 5 review / 123 failed** (`OCR_LEGACY_AUDIT.md:106`; `PHASE2-RULES.md` baseline). Under the parameter-free `ExtractionQualityGate` triad (no text / < 200 chars / all pages empty) **U-extract = 0 and U-structure = 123** — every unclaimed Tesseract read is "usable" by the admitted criteria and therefore Class B (`PHASE2_RULINGS.md:160-165`; `tools/phase2_trigger_split.py` docstring). The alphanumeric-density signal surfaces 23 of them (0.4138–0.6991) but is corpus-fitted and SURFACE-ONLY (Ruling B; `ocr/escalation.py:218-267`). U by profile: scanned 111 / mixed 12; by reason: `no_parser_matched` 89 / `parser_declined` 34; truncation-flagged Tesseract reads 3 (1 in U) (`PHASE2-RULES.md:19-24`).
- **Honest reading for the plan:** whether those 123 are Tesseract text-quality failures or genuine layout gaps is NOT known — the earlier W3-5 diagnosis said "text quality, not layout knowledge" (`W3_5_VISUAL_RUNG.md:17-20`), the Phase 2.0 gate says "usable" only because its criteria are deliberately minimal. Ruling A/B forbid routing them to Paddle *as an automatic production hop*; Gustavo's new brief §13 explicitly allows Paddle to be applied to unresolved genuine statements in the research wave even where text exists.
- Test coverage gap: Tesseract has no default-suite invocation (F-5) — the committed 6 image-only corpus artifacts pin its reads (`tests/corpus_cache/README.md`); `build_corpus_cache.py` refuses to overwrite on OCR drift.
- Plausibility as a cheap `local_free` geometry source: technically yes (TSV gives word boxes + per-word conf in pixel space; `PageFrame.pixel` exists), and it is the only local $0 extractor on the host today (tesseract 5.5.0 present, no local paddleocr — `PHASE2-1-PADDLE.md:34`). Its recognition quality on this corpus is unmeasured beyond the outcome split above.

## 7. House format for a Phase 2 milestone (umbrella card + cell cards)
Derived from `docs/agent-handoffs/PHASE2-1-PADDLE.md` (umbrella) and `P21-PADDLE.md` / `P21-ROUTING.md` (cells); the BATCH9-RULES / PHASE2-RULES report contract; the "material design decision" format Gustavo required.

Umbrella card sections, in order: **Authority** (rulings + architecture sections + rules files; the governing invariant restated) → **Objective (exact)** incl. expected coverage movement and the floor → **Baseline (verified before anything moved)** table (main/HEAD SHA, tag, train branch, floor + run of record + cold cache path (READ-ONLY), stage versions, suite/guards/conformance/gate counts, trigger counts, local toolchain, remote host facts with values never written) → **Scope — bounded cells, disjoint file ownership** table (cell · card · delivers · cases) + composition order → **Material design decisions D1..Dn**, each in the fixed format *expected approach → what changed → why better → new risks → tests/tripwires* → **contracts** (evidence/config/worker/API) → **design per subsystem** → **Provenance / lineage** → **Artifact / cache / replay implications** (stage/schema versions, which cache is read-only, which cold cache the train writes) → **Runtime / cost telemetry** (the exact metric list) → **Required tests — numbered cases mapped to cells** + mutation tables + tripwires + live proofs deselected by default → **Corpus measurements at closure** (the exact list) → **Regression gates** (per cell: newly validated = 0 unless a coverage card, preserved all identical, mutation tables complete, privacy scan 0, message scan 0, secrets scan 0; at the train: union cohort replay, `floor.sh`, cold run vs run of record with `--fail-on-regression`, remote CI run id, live proof recorded once by Ocean) → **Adversarial review plan** (attack list; findings reproduced before acceptance; BLOCK/MAJOR close pre-compose; re-review green; Ocean composes; cells never merge/push; model policy per the override) → **Rules delta** (train/worktree/branch naming `train<N>` / `.claude/worktrees/mt<N>-<card>` / `wave<N>-<card>`; network egress allowed; secrets; customer-data scope; Python 3.14 local / 3.12 CI) → **Explicit exclusions** (opportunities are DOCUMENTED in the cell's W3 section, not built) → **Completion criteria → STOP** (closure report to Gustavo; the next phase does not begin; rulings requested, not assumed) → **Closure** (appended by Ocean).

Cell card sections: read-first list → Why → Design (ruled — do not re-decide) → Files you own (exact; nothing else) → Cases you must prove → Mutation table (every mutant, every killer named) → Proof floor (full suite; 5 canonical guards; 7 conformance files; `corpus_gate.py` GREEN; `pytest -m corpus`; cohort replay `--expect-identical` at base and closure; privacy/message/secrets scans 0; one harness at a time) → Report contract (population · root cause · solution · newly validated · previously validated preserved · regressions · failure-class evidence · escalation evidence · remote evidence · commits · proof-floor exits · privacy + secrets counts · risks last; W3 section `# §<CARD> — …`) → Exclusions.

Standing conventions: commit messages in classes not instances; caches read-only; every mover named by SHA in advance; "claimed != validated"; never summarise a cell as green on a net count; a completion gate ends in STOP and a closure report; rulings are recorded in `PHASE2_RULINGS.md` before any code depends on them.
