## Initial findings, subsequently closed

### MAJOR-1 — a failed inspection can certify that retention is clean

`tools/paddle_wave.py:695` constructs `_ATTESTATION_COMMAND` with shell pipelines that discard errors
from `ps` and `find`. Each pipeline ends in a successful counter, and the final `echo` determines the
command's exit status. `attest_retention` then sees all required numeric fields and sets `inspected=True`.

I executed the exact committed shell against a temporary synthetic runtime directory, with only the
process-list producer substituted so unrelated host processes were never inspected. Two independent
failure shapes both returned a false clean attestation:

| probe | shell exit | inspected | passed |
|---|---:|---|---|
| clean synthetic runtime, empty process list (control) | 0 | true | true |
| runtime directory does not exist; `find` fails | 0 | true | true |
| `ps` fails instead of returning a process list | 0 | true | true |

This violates the documented distinction between no retained files and an inspection that could not
run. A passing live attestation cannot close this gap: it exercises the successful inspection only.
Check the runtime directory, preserve each inspection command's exit status, and add exact-shell pins
for these failures. The fix must also preserve the already-correct inspector-versus-worker distinction.

Evidence: `discovery_reports/train13-logs/rev23-wave/retention-probes.log`, generated by the private
`retention_probes.py` against `2d74305`; `EXIT=0` means all probes executed, not that their false passes
were accepted. No external request or customer document was involved.
