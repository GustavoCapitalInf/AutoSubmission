# Analysis API v1

Auto-Submission (`apps/auto_submission/`) sends a merchant's bank statement PDFs to this web app and reads back the
deal's underwriting figures over HTTP. This document is the contract between them. Its source is
`webapp/api/contract.py`: `docs/api/v1.schema.json` and the reference at the end of this page are generated from it
by `python -m tools.api_contract --write`, and `python -m tools.api_contract --check` fails when either is stale.

## Call it

The base URL is `https://<host>/api/v1`. Every request sends the API token as a bearer token.

```python
import os, time, uuid
import httpx

api = httpx.Client(base_url=os.environ["ANALYSIS_API_URL"],            # https://<host>/api/v1
                   headers={"Authorization": f"Bearer {os.environ['ANALYSIS_API_TOKEN']}"}, timeout=120)

package_id = application.analysis_package_id or str(uuid.uuid4())     # saved with the application BEFORE the PUT
files = [("files", (path.name, path.read_bytes(), "application/pdf")) for path in pdfs]
response = api.put(f"/packages/{package_id}", files=files)             # 201 created, 200 identical replay, 409 conflict
response.raise_for_status()
package = response.json()
while package["status"] == "processing":
    time.sleep(int(response.headers.get("Retry-After", "10")))
    response = api.get(f"/packages/{package_id}")
    response.raise_for_status()
    package = response.json()

if package["review"]["required"] or not package["complete"]:
    send_to_underwriter(application, package)                           # figures may be partial or null
else:
    fill_funder_form(package["figures"])                                # integer cents; null = not established
for document in package["documents"]:
    if document["status"] == "failed":
        ask_merchant_again(document["filename"], document["failure"]["code"])
```

The caller chooses the package id and saves it before the first PUT. After a timeout or a lost reply, the same PUT
with the same id and the same files answers again without creating anything, so a retry is always safe. A GET with
the id recovers the package after a restart without sending the files again.

## Set up the token

The operator sets one secret on the host, and the same value as `ANALYSIS_API_TOKEN` in Auto-Submission:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"   # a new random token
fly secrets set WEBAPP_API_TOKEN=<the token>
```

- The API is off until the token is set: every API request answers 503 `api_disabled`. It is also off when the token
  is shorter than 32 characters or equal to `WEBAPP_AUTH_PASSWORD`.
- The token opens `/api/v1` and nothing else. The browser's password never opens the API, and a request that carries
  a bearer token to any other route is refused with the browser's 401, whether or not a browser password is set.
- `/healthz` needs neither.
- To rotate the token, set the new value on both apps; requests with the old one answer 401 from the restart on.

## Requests

| Request | Success | Errors |
|---|---|---|
| `PUT /packages/<package_id>` with multipart `files`: 1 to 25 PDFs | `201` and `Location: /api/v1/packages/<package_id>` for a new package; `200` for an identical replay. The body is the package. | `400`, `409`, `413`, `503`, `507` |
| `GET /packages/<package_id>` | `200`, the package. While it is processing, `Retry-After: 10`. | `404` `package_not_found` |
| Any other path or method under `/api/v1` | | `404` `route_not_found`, `405` `method_not_allowed` |
| Every request | | `401` `unauthorized` with `WWW-Authenticate: Bearer realm="bank-statement-analysis-api"`; `503` `api_disabled`; `503` `storage_degraded`; `500` `internal_error` |

- `package_id` is a UUID in lowercase canonical form, such as `0f8fad5b-d9cb-469f-a165-70867728950e`; any other id
  answers 400 `invalid_package_id`.
- The PDFs follow the dashboard's upload rules, checked for the whole request before anything is stored: at most 25
  files and 100 MB per request, each file a `%PDF-` document that is not password-protected and has at most 500
  pages, and no filename with a line break or `-->`. One refused file refuses the request, and its name is in
  `error.filename`.
- A replay is identical when it sends the same filenames with the same bytes in the same order. Different statements
  under a known id answer 409 `package_conflict`: send them under a new id.
- When the server started with storage it could not write, packages can still be read but nothing can be submitted
  (503 `storage_degraded`). When it could not read its storage either, every API request answers that.
- Every response is JSON and carries `Cache-Control: no-store`. An error is always this envelope, with the code's one
  fixed message from the catalog below:

```json
{"error": {"code": "not_a_pdf", "message": "a file is not a PDF", "filename": "march.pdf"}}
```

## Package states

A package is `processing` while any of its statements is queued or processing. It then shows each statement's
progress and no figure. Once every statement is finished it is `ready`, and it stays ready.

A ready package lists each statement, in submitted order, as one of:

- `analysed`: its accounts, each `included` in the figures or `excluded` with the reason. An exclusion with a null
  `account_index` leaves out the whole statement: its main account was not verified or printed no activity.
- `failed`: no analysis, with a `failure.code`. Nothing of it is counted, and the other statements still give
  figures.
- `duplicate`: the same statement as another of the package (`duplicate_of`). Nothing of it is counted twice.

`complete` is true when every statement was analysed, no account was left out (repeats aside) and no section of a
statement was omitted. `review.required` is true unless `review.decision` is `approved`, the package is complete and
no statement was analysed under older classification rules. `review.decision` is the analysis' publication status,
not a funder's credit decision. Send a package that needs review to an underwriter.

## Reading the figures

- Money is integer cents in the currency named beside it, rates are integer basis points (857 is 8.57%), counts are
  whole numbers, days are ISO dates and months are `YYYY-MM`. No field is a fractional number, so no body carries
  NaN or Infinity.
- A null figure was not established. It is never a zero. True revenue is null when an included account's revenue is
  not established; the average daily balance when no daily ledger was validated; negative days when a count is not on
  the printed-day basis. Monthly figures and the average daily balance are null when two accounts of one statement
  would be averaged. A figure the store holds as NaN or Infinity is null.
- `figures` is null when no account entered the package (every statement failed or was left out), so such a package
  never shows a zero.
- When the statements are in more than one currency, or one names none, `currency` is null, `currency_refusal` says
  why, and every money figure is null. Counts stay.
- An account's figures are the package's: transfers between accounts of one statement are removed, so the included
  accounts add up to the package. They can differ from the same statement viewed alone in the dashboard.
- Account numbers are only ever `****` and the last four digits. No transaction row, description or evidence list is
  published.

## The fixed reading

Every figure is read the same way: negative days on printed days only, Zelle deposits counted as True revenue, and
every flag group shown. These are the owner's display defaults (`analysis/display_settings.py`); the settings saved in
the dashboard never change an API body. A statement whose stored analysis cannot be read with Zelle counted is
`failed` with `reading_unavailable` and is left out of the figures.

## Snapshot and revision

Each response reads all of a package's statements at one moment, so a statement that finishes or is reviewed while a
response is built is read as it stood before. A ready package's figures still change when an underwriter reviews a
deposit or re-analyses a statement in the dashboard. `revision` is the SHA-256 of the body without `revision`: keep
the body and its revision when you use its figures, and compare the revision to see whether anything changed.

## Versioning

The path carries the major version and `api_version` the minor one. Within 1.x a change only adds: a new field, or a
new value of an open-vocabulary string such as an exclusion `reason`. Read fields by name and ignore any you do not
know. Anything else needs v2, served under `/api/v2` beside v1: removing, renaming or retyping a field, making a field
nullable, a new value of a closed set (`status`, `decision`, a failure or error code, `quality`, `corporate_use`,
`integrity_risk`, `currency_refusal`), a new unit, or a different reading. `tests/test_api_contract.py` pins the
schema's SHA-256 to `api_version`, so any schema change needs that decision.
